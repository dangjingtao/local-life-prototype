## 1. 版本目标

V0.3 不改变“便利店 / 线上商城 / 智慧抗衰”三大业务域，也不改变 V0.2 已建立的购物车隔离、自提 / 短配、商城全国快递、统一账号与统一权益语义。

本版只解决四类明确增量：

1. 便利店商品浏览从“单品 / 套餐点击切换”升级为连续浏览。
2. 便利店自提从“数字取货码”升级为“二维码 + 数字码”双凭证，并在 PC 形成双通道核销。
3. 消费积分从“账户中可看、便利店可抵”升级为“消费可得积分可见 + 商城可抵 + 场景倍率统一”。
4. 既有“私域承接”概念落成明确的“加入社群”入口、指引页与消费后轻提示。

成功意味着：用户可连续扫货、可用双凭证取货、在消费前明确看到积分收益并在商城使用积分，同时能在消费后进入门店社群；Mobile / PC 使用同一 Shared Mock 语义，不出现第二套订单、积分或核销模型。

## 3. 继承规则

V0.3 继续遵守：

- 便利店先确定门店；不同门店购物车独立。
- 便利店与商城不混单。
- 便利店继续支持自提与约 3 公里短距配送。
- 商城继续只表达全国快递消费语义，不恢复 Storefront / Channel 消费者心智。
- 统一用户 ID、积分、券、会员资产跨业务域共享。
- Mobile 为消费者侧；PC 为门店 / 平台履约与运营侧。
- Mock 数据必须跨页面自洽；未确认规则显式保持 Candidate / Unknown。
- 不建设真实支付、真实库存、真实扫码硬件、真实企业微信接口或生产级后端。

## 4. R01 · 便利店连续商品浏览

### 4.1 当前问题

当前便利店双栏浏览已经具备左侧固定大类、右侧紧凑商品行、单品 / 套餐胶囊切换、悬浮购物栏和购物车 Sheet。

问题只在于：用户必须主动点击“单品 / 套餐”才能看到另一组商品，浏览被人为切断。

### 4.2 连续顺序

右侧商品区按以下顺序组织：

```text
大类 A
├─ 单品
└─ 套餐
↓
大类 B
├─ 单品
└─ 套餐
↓
大类 C
...
```

用户持续向下滑动时：

**当前大类单品 → 当前大类套餐 → 下一大类单品 → 下一大类套餐**

反向滑动按相反顺序成立。

### 4.3 单品 / 套餐表达

现有胶囊不得继续作为“隐藏另一组商品”的过滤器。

可改为：

- 分段标题；或
- 当前位置 / 快速锚点。

无论视觉采用哪种方式，都必须满足：

> 不点击“单品 / 套餐”也能看到全部商品。

### 4.4 分类滚动联动

左侧大类栏继续保留。

- 点击左侧分类：右侧滚动到该大类起点。
- 用户滚动跨入下一大类：左侧选中态自动更新。
- 反向滚动回上一大类：选中态同步回退。
- 程序化定位不得与滚动监听互相抖动。

### 4.5 不改内容

本需求不得重做：

- 门店上下文；
- 商品搜索；
- 商品卡信息层级；
- 加购数量控制；
- 售罄 / 不可售状态；
- 商品详情；
- 购物车 Sheet；
- 独立购物车；
- 结算、自提、短配。

## 5. R02 · 自提双凭证与双通道核销

### 5.1 Mobile 双凭证

沿用 V0.2 自提状态：

```text
支付成功 → 备货中 → 待取货 → 核销完成
```

V0.3 不重做状态机，只给同一自提订单增加：

- 取货二维码；
- 数字取货码。

支付后的订单状态页 / 后续订单详情均可再次查看。

### 5.2 凭证状态

原型至少表达：

- 未生效：尚未进入可取货条件。
- 可核销：待取货 + 当前处于所选取货时段 + 未核销。
- 已失效：已核销或不再满足有效条件。

二维码和数字码共享同一个 redemption 状态。

### 5.3 PC 双通道

PC 在 V0.2 T022 便利店履约后台稳定后增加两条入口：

**扫码 Mock**

二维码 → 匹配同一订单 → 核销确认 → 完成。

**数字码**

输入数字取货码 → 匹配同一订单 → 核销确认 → 完成。

两种方式不得创建两套订单或两套核销记录。

### 5.4 原型安全边界

需求中的“防止截屏代取”在本原型只验证：

- 与取货时段绑定；
- 单次核销；
- 核销后立即失效。

不宣称已实现生产级动态 Token、防截屏或防转发安全能力。

## 6. R03 · 消费积分升级

### 6.1 已有能力不得重复施工

V0.2 已具备：

- 统一积分账户；
- 积分中心；
- 便利店结算积分开关；
- 积分抵扣金额；
- 应付金额联动；
- 订单明细积分抵扣。

V0.3 不建立第二套便利店积分抵现。

### 6.2 消费积分倍率

V0.3 确认以下消费获得倍率：

| 场景 | 获得积分 |
| --- | ---: |
| 便利店 | 消费 1 元 = 1 积分 |
| 线上商城 | 消费 1 元 = 1 积分 |
| 智慧抗衰 | 消费 1 元 = 2 积分 |

倍率进入 Shared 统一规则，页面不得分别硬编码。

### 6.3 本单可得积分

便利店购物车、便利店结算、商城购物车、商城结算均展示：

> 本单预计可得 +XX 积分

结算数据变化后，展示值必须同步变化。

### 6.4 商城积分抵现

商城结算增加：

- 当前积分余额；
- 本单可使用积分；
- 可抵金额；
- 使用积分开关；
- 积分抵扣明细；
- 应付金额实时联动。

商城仍保持自己的购物车与全国快递订单语义。

### 6.5 仍未确认

以下规则原需求没有给出，不得固化：

- “消费 1 元”的计分基数：原价 / 优惠后 / 实付金额。
- 积分抵人民币正式兑换比例。
- 单笔最高抵扣比例。
- 非整数积分取整规则。

项目现有“100 积分 = ¥1”继续为 Candidate，仅用于原型抵现演示，除非后续业务明确确认。

## 7. R04 · 加入社群

### 7.1 常驻入口

“我的”新增常驻入口：

**加入社群**

点击进入独立社群指引页。

常驻入口不受消费后提示频控影响。

### 7.2 社群指引页

展示：

- 企业微信群活码 / 社群二维码 Mock；
- 社群权益说明：专属优惠、上新通知、直播优惠；
- 长按识别 / 保存图片的可理解交互表达。

原型不接真实企微活码服务。

### 7.3 消费后轻提示

便利店：

- 支付成功；
- 取货成功；

展示轻量条幅：

> 加入门店社群，获取更多福利

点击进入社群指引页。

不得使用阻塞主任务的强制 Modal。

### 7.4 7 天频控

同一用户 7 天内不重复展示消费后社群提示。

原型至少可以验证：

- 首次应提示；
- 已提示 / 7 天内不再提示。

“我的 → 加入社群”始终可访问。
