# T019 商城 UI 返工视觉基准

- Status: CONFIRMED BASELINE
- Target: Mobile / V0.2 / T019 visual rework
- Canonical viewport: `390 × 844`
- Confirmed by: Tomz
- Confirmed at: 2026-09-02

## 1. 基准来源与优先级

本文件把 2026-09-02 已确认的五屏商城 UI 稿转成可执行的布局合同。该稿覆盖：

1. 商城首页
2. 商品详情
3. 商城购物车
4. 结算确认
5. 订单 / 物流详情

用户已明确确认：**交互没有问题；除颜色改用项目现有 Design Token 外，要求严格按该稿的交互、模块顺序、关键宽高布局施工。**

优先级：

1. T015 / T016 / T019 已确认业务事实与实际功能点
2. 本视觉基准的交互、模块顺序、关键宽高比例和信息层级
3. `@prototype/design-system/tokens.css` 的颜色 token
4. 现有实现中不与以上冲突的细节

不得因为“响应式优化”“组件复用”“更符合现有 Card 结构”等理由自行改变确认稿。

## 2. 不可变业务边界

- 商城只表达全国快递 / 一件代发，不出现便利店门店库存、自提或 3 公里短配。
- 商城购物车独立，不与便利店混单。
- 保留现有 Storefront / Channel 数据语义，但消费者界面使用“商城来源 / 店铺来源 / 官方商城 / 私域精选”等正常语言，不直接暴露工程模型术语。
- 保留现有商城内搜索、分类、商品详情、加入购物车、立即购买、独立购物车、结算、订单状态推进、物流状态演示。
- 保留全局搜索进入指定商城商品的 handoff；不得因为页面重构让该入口失效。
- 不新增真实支付、真实物流、评价、直播、客服系统、收藏持久化、外部平台跳转等未确认能力。
- UI 稿中的示意内容若仓库 fixtures 不存在，必须映射到现有实体；不得为了还原画面创造新的业务规则。

## 3. Token 规则

颜色不得抄 UI 稿中的橙色值。必须使用现有 token：

- 背景：`--color-background`
- Surface：`--color-surface` / `--color-surface-subtle`
- Border：`--color-border`
- 主文字：`--color-text-primary`
- 次文字：`--color-text-secondary` / `--color-text-tertiary`
- 主色：`--color-primary`
- 主色 pressed：`--color-primary-pressed`
- 主色浅底：`--color-brand-subtle`
- Success / Warning / Danger：使用对应 semantic token

圆角 / 触控仍使用项目 token：`--radius-control`、`--radius-container`、`--radius-overlay`、`--touch-min`。普通 Card 不额外堆重阴影。

**只有颜色被允许与确认稿不同。** 布局、密度、相对尺寸、交互位置必须按本文件执行。

## 4. 全局几何合同

Canonical ready state 使用 `390 × 844` 浏览器视口。

- 页面宽：390px
- 普通内容左右 inset：16px
- 普通内容可用宽：358px
- 底部一级导航：64px（Home / Cart 可见）
- 页面专属固定操作栏：72px
- 触控目标：不低于 44px
- 模块垂直间距：8 / 12 / 16px 为主，不使用当前实现的大段 `space-y-6` 把商城拆成松散 Demo Card
- canonical ready state 的关键块高度容差：±4px
- 商品图片区域使用固定 aspect / 高度，禁止因为缺少素材退回文字色块
- 文案允许在真实 fixture 名称下发生一行以内的自然差异，但不得因此改变主块几何；超长内容用 clamp / truncation 处理

### App chrome

为了匹配确认稿，商城不继续套用当前通用 `LOCAL LIFE · V0.2 PREVIEW` sticky header。

- Mall Home 使用商城专属头部。
- Product Detail / Checkout / Order 使用页面专属 top bar。
- Home 与 Cart 保留一级底部导航。
- Product Detail / Checkout / Order 隐藏一级底部导航，使用确认稿对应的固定底部操作区或返回路径。
- 这只是 Mall 展示层 chrome 调整，不改变 T016 的一级 IA 和 Home 全局搜索能力。

## 5. Screen A · 商城首页

### 垂直顺序

1. 商城专属头部 / 全国快递提示 / 购物车入口
2. 商城来源选择区
3. 商城内搜索
4. 横向分类
5. 运营活动 Banner
6. “为你推荐”双列商品区
7. 满额包邮说明条
8. 一级底部导航

### 390px 几何

- 商城头部：`92px`，全宽视觉区；内部左右 16px
- 来源选择区：`108px`；距头部 0–8px，3 个来源卡在一行时等宽；若 fixtures 数量不同，保持单行横向布局，不增加第二层解释卡
- 搜索框：`44px` 高
- 分类轨：`36px` 高，横向滚动
- 活动 Banner：`112px` 高，宽 358px
- 推荐区标题：`28px` 行高区
- 商品双列：两列 gap `10px`；单卡宽约 `174px`
- 商品图：`122px` 高；商品卡 ready state 总高约 `216–224px`
- 包邮说明条：`52px` 高
- 一级导航：`64px`

### 信息层级

头部第一眼是“线上商城 + 全国快递 + 购物车”，不是技术解释。来源选择使用消费者语言。首页首屏必须能看到搜索 / 分类 / 活动的一部分，不能让来源模型卡占掉大半首屏。

商品卡必须包含：真实感商品图、商品名、规格、价格、可选原价 / 优惠、全国快递 / 包邮类轻标签。不得把 `Storefront`、`Channel`、`Mock`、`planned`、`integrationStatus` 作为视觉内容。

## 6. Screen B · 商品详情

### 垂直顺序

1. 48px top bar：返回 + 辅助操作 / 购物车入口
2. 商品主图
3. 商品标题 / 卖点 / 价格
4. 规格
5. 促销
6. 配送 / 运费
7. 可用优惠券
8. 固定购买操作栏

### 390px 几何

- Top bar：`48px`
- 商品主图：`286px` 高，宽 390px 或贴近全宽；图片不得放在普通小 Card 中
- 标题 / 价格主信息区：约 `132px`
- 规格行：`44px`
- 促销行：`52px`
- 配送 / 运费区：`72px`
- 优惠券区：`76px`
- 固定购买栏：`72px`
- 购买栏中“加入购物车 / 立即购买”占主要宽度，按钮高度 `48px`

商品主图、标题、价格是绝对主视觉；配送解释和模型说明不得抢占上半屏。保留现有商品规格、优惠、包邮规则和购物车逻辑。

## 7. Screen C · 购物车

### 垂直顺序

1. 标题 + 管理入口
2. 当前商城来源
3. 商品列表
4. 商品小计 / 运费 / 包邮进度提示
5. 固定结算栏
6. 一级底部导航

### 390px 几何

- 标题区：`56px`
- 来源提示：`44px`
- 单商品行：`128px`；缩略图 `82 × 82px`
- 数量 stepper 单按钮触控宽高 ≥44px
- 金额汇总区：`116px`
- 固定结算栏：`68px`
- 一级导航：`64px`

商品列表以商品为中心，不显示“Storefront 独立模型”说明段落。当前来源只用一行正常消费者语言表达。

## 8. Screen D · 结算确认

### 垂直顺序

1. 52px top bar
2. 收货地址
3. 店铺来源 / 配送方式 / 备注
4. 商品明细
5. 金额明细
6. 固定提交订单按钮

### 390px 几何

- Top bar：`52px`
- 地址卡：`104px`
- 来源 / 配送 / 备注组合区：`116px`
- 单商品摘要行：`72px`，缩略图 `56 × 56px`
- 金额区：`132px`
- 固定提交区：`72px`

正常页面不显示“T019”“演示数据”“Mock 订单”“不发起真实支付”等工程说明。原型边界应由 Prototype Runtime / 测试 /文档承担，不进入主消费界面。

## 9. Screen E · 订单 / 物流详情

### 垂直顺序

1. 52px top bar
2. 订单状态 Hero
3. 订单号
4. 三段物流进度
5. 物流公司 / 运单号与轨迹
6. 订单信息 / 收货信息
7. 底部操作

### 390px 几何

- Top bar：`52px`
- 状态 Hero：`112px`
- 订单号区：`44px`
- 三段进度：`72px`
- 物流信息与轨迹 ready state：约 `228px`
- 订单信息：约 `136px`
- 底部操作栏：`72px`

现有状态仍为 `待发货 → 运输中 → 已签收 / 已完成`。允许用现有模拟按钮推进状态，但消费者主内容不得显示 `Mock order`、`MOCK-SF-*` 之类工程命名；演示运单号可以用正常格式的虚拟编号。

## 10. 商品视觉要求

- 继续使用 T015 / T019 已有商品实体，不新增商品业务规则。
- 为现有商城商品补真实感本地演示图 / 包装图资产，使首页卡片与商详都能复用同一商品视觉。
- 不使用“色块 + 商品名”冒充商品图片。
- 图片裁切以商品包装完整可识别为优先；首页卡 `object-fit: cover/contain` 由素材决定，但同类卡保持一致。

## 11. 禁止的“自作主张优化”

- 不把来源选择改成抽屉、下拉或新页面。
- 不把双列推荐改成单列列表。
- 不把活动 Banner 删除或挪到推荐商品之后。
- 不把商品详情重新拆成大量通用 Card。
- 不改变“加入购物车 / 立即购买”的并列购买动作。
- 不把购物车改成便利店式底部小购物栏。
- 不增加选中结算、多地址管理、支付方式、发票、售后、评价、收藏持久化等当前未实现能力。
- 不因 Design Token 主色与确认稿不同而改变任何布局结构。

## 12. 验收方式

T019-R5 必须在真实 Chromium `390 × 844` 下逐屏对照本基准，至少留存五个 canonical ready state 实屏证据。

视觉判断不是“差不多”：

- 模块顺序必须一致。
- 关键块高度按本文 ±4px 验收。
- 首页双列商品卡、详情大图、购物车行、结算明细、物流时间线的相对占比必须一致。
- 颜色只检查是否正确消费项目 token，不拿确认稿橙色做像素匹配。
- 功能回归通过不能替代该视觉验收。
