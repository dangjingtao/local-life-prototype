## Why

T031 完成了浏览页的双栏布局和密度升级，购物车和结算页也需要对应升级以保持体验一致性：

- 当前购物车是独立页面，便利店场景下用户更希望"边逛边加"，不需要跳页打断浏览

- 结算页信息平铺，分组不清晰，用户扫描效率低

- 商详底部操作栏不够突出，加购路径不明确

参考 7-Eleven 的弹层购物车 + 卡片式结算页分组，提升便利店场景的操作效率。

## Scope

**做：**

- 弹层购物车（半屏 Sheet）：点击底部购物栏从底部滑出，展示商品清单、数量控制、全选/清空、合计金额、去结算 CTA

- 弹层购物车与独立购物车页并存：弹层用于快速确认，独立购物车页仍可通过底部 Tab 访问（保留完整编辑能力）

- 弹层购物车内展示库存紧张提示（红色标签）

- 商详页信息层级优化：主图 → 品名/规格 → 价格/会员价/促销 → 商品描述 → 门店信息（辅助层级）

- 商详底部固定操作栏：数量控件 + 加入购物车 + 立即购买

- 结算页卡片式分组：自提点信息 → 联系人/手机号 → 取餐方式（自提/短配大按钮二选一）→ 商品清单 → 金额明细，每组有明确卡片边界

- 结算页补充辅助选项：购物袋开关、订单备注

- 配色完全使用现有 Com Design token

**不做：**

- 不改动业务流程和数据结构（T018 保持不变）

- 不新增真实支付、真实物流等后端能力

- 不改动 T031 已完成的浏览页结构

## Acceptance

1. 点击底部购物栏弹出半屏购物车 Sheet，展开/收起交互流畅
2. 弹层购物车展示商品清单、数量加减控件、全选/清空、合计金额、去结算按钮
3. 弹层购物车内加减数量后，底部购物栏金额和数量同步更新
4. 弹层购物车底部结算按钮固定，不随商品列表滚动
5. 库存紧张商品在弹层购物车内有红色提示标签
6. 商详页信息层级清晰：主图最大，价格/促销第二，描述第三，门店信息最弱
7. 商详底部固定操作栏：数量控件 + 加入购物车 + 立即购买，任意滚动位置可达
8. 结算页采用卡片式分组，每组有明确的视觉边界和组标题
9. 取餐方式（自提/短配）采用大按钮二选一，选中态视觉明确
10. 结算页包含购物袋开关、订单备注等便利店高频辅助选项
11. 从浏览页 → 弹层购物车 → 结算页链路连续，不出现断裂或重复确认
12. 正常路径不出现 mock / fixture / 可售上下文等内部术语
13. 配色完全使用现有 Com Design token，不新增主题色变量
14. 390×844 浏览器走查通过，无横向溢出
15. typecheck、build 与 Playwright 回归通过
