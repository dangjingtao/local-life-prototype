## Human acceptance checklist

### A. 便利店连续浏览

- [ ] 进入便利店并选择云岭社区店。
- [ ] 不点击“单品 / 套餐”过滤器即可连续看到：当前大类单品 → 套餐 → 下一大类。
- [ ] 点击左侧分类能定位右侧；自然下滑 / 上滑时左侧高亮同步变化。
- [ ] 搜索、商详、加购、购物车 Sheet、完整购物车仍自然可用。
- [ ] 390×844 下底部购物栏 / 一级导航不遮挡最后商品。

### B. 便利店积分 + checkout

- [ ] Cart Sheet / 完整购物车能看到“本单预计可得积分”。
- [ ] 改数量后预计可得积分变化。
- [ ] checkout 信息分组清晰，仍可切换自提 / 约 3 km 短配。
- [ ] checkout 显示预计可得积分，同时原有积分抵现 / 应付行为没有出现第二套状态。
- [ ] 页面没有 Shared / fixture / Mock order 等不应暴露的工程术语（明确标注的二维码原型能力边界除外）。

### C. 自提双凭证

- [ ] 提交自提订单后，订单号与**纯数字取货码**视觉上能明确区分。
- [ ] 备货中显示凭证未生效。
- [ ] 模拟备货完成后，二维码 + 数字取货码同时可核销。
- [ ] 两种凭证明确属于同一订单 / 同一次核销。
- [ ] 核销完成后两种凭证同时失效。
- [ ] 返回便利店并重新打开最近自提订单，仍是同一订单 / 同一凭证状态。

### D. PC 双通道核销

- [ ] PC 便利店履约后台能看到扫码核销与数字码核销入口。
- [ ] QR Mock 能命中 Mobile 同一自提订单。
- [ ] 输入 Mobile 展示的纯数字码能命中同一订单。
- [ ] 任一通道核销后，另一通道不可重复核销。
- [ ] 页面不宣称已接真实摄像头 / 真实扫码 SDK。

### E. 商城积分闭环

- [ ] 商城购物车显示预计可得积分，数量变化后同步变化。
- [ ] 商城 checkout 显示当前积分、积分抵现开关、抵扣金额与应付联动。
- [ ] 关闭积分抵现后应付金额恢复。
- [ ] 消费者界面没有 Storefront / Channel / 店铺来源心智。
- [ ] 商城继续表达全国快递，不与便利店购物车混单。
- [ ] Candidate 抵现比例没有被包装成正式业务规则。

### F. 社群承接

- [ ] “我的 → 加入社群”常驻入口存在，并能进入社群指引页。
- [ ] 指引页有二维码示意、专属优惠 / 上新通知 / 直播优惠三类权益。
- [ ] 页面明确原型二维码边界，不伪装真实企业微信活码。
- [ ] 便利店支付成功出现轻量社群提示，不阻塞订单主任务。
- [ ] 取货完成具备对应提示场景。
- [ ] 点击提示进入同一个社群指引页。
- [ ] 7 天频控由 T045 自动化证据确认；人类验收不要求实际等待 7 天。

### G. 总体产品 / 视觉

- [ ] Mobile 一级 Tab 仍是：首页 / 便利店 / 商城 / 智慧抗衰 / 我的；V0.3 没新增一级社群 Tab。
- [ ] 390×844 主链无明显溢出、遮挡、跳动、假按钮或工程态文案。
- [ ] PC 核销页在桌面视口信息层级清楚、操作结果可理解。
- [ ] 三业务域、统一积分 / 用户 / 核销关系在体验上没有出现互相矛盾的第二套事实。
